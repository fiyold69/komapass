# 目的・用語・MVPの範囲

KomaPass（仮）が何のためのアプリで、MVPで何を作るか。ほかのファイルは、ここを前提に書く。

## 目的

### アプリの目的

- 個別指導塾の講師が「出られないコマ」の代講を募集し、他の講師が申し出て、依頼者が1人を選んで成立させる
- LINEで一人ずつ頼む手間と、教室長が誰が入るかを把握しきれない問題を減らすため
- 正確な書き方は未決（[open-questions.md](open-questions.md) の「アプリの目的を正確に書く」）

### 作る目的

1. 作者がフルスタックの基礎を手で身に付けること（就活のポートフォリオ）
2. 完成後、実際の塾で使ってもらうこと（実運用）。ポートフォリオとしても、実際に使われている方が強いため

実運用の前提（塾の了承、バックアップなど）は [operations.md](operations.md) と [security.md](security.md)。

### アプリの名前

- KomaPass（仮）

## 用語

| 用語 | 意味 |
| --- | --- |
| コマ | 「日付＋時限の番号」で表す授業の枠 |
| 依頼 | 講師が「このコマに出られない」と代講を募集すること |
| 申し出 | 他の講師が「代われます」と手を挙げること |
| 成立 | 依頼した講師が、申し出た人から1人を選んだ状態 |
| 有効な依頼 | 取り消していない依頼（募集中・申し出あり・成立） |
| 教室長 | 教室の責任者（役割名は `admin`） |

用語の整理（状態・操作・人の呼び方と、コードで使う英語の名前との対応）は未決（[open-questions.md](open-questions.md) の「用語の整理」）。

## MVPの範囲

| 箱 | 中身 |
| --- | --- |
| MVPでやる | 依頼の作成、申し出、申し出の取り下げ、依頼者が選んで成立、取り消し、期限切れの非表示、ログイン（LINE）、承認待ち、役割ごとの権限、教室長の成立一覧、役割の付与のスクリプト |
| MVPの後 | 通知（LINEなど）、教室長の承認、画面から役割を付ける機能、教室長が時限表を画面で入れる機能、メールとパスワードのログイン（#23）、メール送信（パスワード再設定など）、利用を止める（#15）、成立一覧で終わった分を見る設定、先着の自動確定、招待、カレンダー表示、複数教室、引き受け条件、Goへの書き直し |
| やらない | 生徒情報の管理、マイクロサービス、Kubernetes |

- 遅れたときは、「MVPでやる」から「MVPの後」へ移す。週1回の振り返りで判断する（[workflow.md](workflow.md)）
