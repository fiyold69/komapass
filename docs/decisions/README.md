# 決定事項（docs/decisions）

KomaPass（仮）で決めたことと、その理由を置く場所。**今の決定だけ**を書く（Wikiのように、いつ読んでも今の正しい内容になっている）。

**決定の正本はこのフォルダ。** ほかの文書と食い違ったら、このフォルダを正とする。

## ファイル一覧

| ファイル | 中身 |
| --- | --- |
| [product.md](product.md) | 目的、用語、MVPの範囲 |
| [business-rules.md](business-rules.md) | 業務ルール（依頼・申し出・成立・取り消し・取り下げ・期限切れ・一覧を見られる人） |
| [auth.md](auth.md) | ログイン、承認待ち、役割の付け方、LINEログイン |
| [db.md](db.md) | DB（MySQL）の設計の約束 |
| [operations.md](operations.md) | 公開先と運用、スクリプトの約束 |
| [security.md](security.md) | セキュリティと公開のチェックリスト |
| [dev-env.md](dev-env.md) | 技術構成、開発環境、道具 |
| [workflow.md](workflow.md) | 進め方、記録の置き場所、AIの使い分け |
| [open-questions.md](open-questions.md) | 未決事項（決まるまでの置き場所） |
| [struggles.md](struggles.md) | 悩んだこと（何に悩み、どう考えて決めたか）。決定の経緯はここに残す |

大きな方針転換（比べた案と選んだ理由を、あとから書き換えずに残すもの）は、`docs/adr/` に置く。

## 書き方の約束

- **今の決定だけを書く。** 決定を変えるときは、本文を書き換える。「決めた日」「変更（日付）」「追記」「補足（日付）」のような、経緯の注記は書かない。経緯（何に悩み、どう考えて決めたか）は [struggles.md](struggles.md) に残す
- **1つの事実は、1つのファイルにだけ書く。** ほかのファイルからは、リンクで参照する
- **未決のものは [open-questions.md](open-questions.md) にだけ書く。** open-questions.md には未決のものだけを置く。決定の一部が未決のときは、中身を書かずにリンクだけを置く（例：「（未決。open-questions.md の『〜』）」）
- **決まったら、3か所を同じPRで直す。** 決定は該当するファイルに書き、どう悩んで決めたかは [struggles.md](struggles.md) に書き、open-questions.md からは消す
- **[struggles.md](struggles.md) の中は、話題ごとに見出しで分ける**（例：業務ルール、認証、DB、進め方）
- **決定は、PRでmainにマージされたものだけを正とする。** チャットで話しただけのものは「案」。決定を変えるPRでは、`docs/decisions/` と CLAUDE.md（と、関係するユーザーストーリーや設計書）を同じPRで直す
- **CLAUDE.md と設計書は例外。** CLAUDE.md はAIが毎回読む要約、ユーザーストーリーなどの設計書は決定をテストの形に言い直したものなので、このフォルダと中身が重なってよい。食い違ったら、このフォルダを正とする
- 確かめきれていないことは「不確か」「要確認」と書き、推測で埋めない
- 塾名・実在の人名・教室名は書かない

## 書式（コピー用）

決定のファイルには、決まった書式はない。見出しの下に、今の決定とその理由を短く書く。

悩んだこと（struggles.md）は、次の書式で書く：

~~~markdown
### 〈何に悩んだか〉

- 状況：〈何を決めようとしていたか〉
- 比べた案：〈案と、それぞれの良いところ・気になるところ〉
- 決めたこと：〈どれにしたか〉
- 理由：〈なぜそれにしたか〉
- 関連：〈Issue・PR・決定のファイルへのリンク〉
~~~
