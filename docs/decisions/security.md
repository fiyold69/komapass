# セキュリティと公開

基本は **「コードは見せる、データは見せない」**。就活で公開するのはコードとダミーデータのデモだけで、本番のURL・画面・データは見せない。確かめきれていない点は「要確認」と書いた。

細かい中身がほかのファイルにあるものは、リンクで参照する。

## コードを公開するとき（就活）

- [ ] **秘密の値をコミットしない**：DBの接続文字列、Better Authの秘密鍵、LINEのチャネルシークレットは `.env` に置き、`.gitignore` に入れる。リポジトリには値を空にした `.env.example` だけを置く
- [ ] **一度でもコミットしたら鍵を作り直す**：履歴から消すだけでは不十分（すでに複製・取得されている可能性がある）
- [ ] **塾を特定できる情報を出さない**：塾名・実在の講師名・教室名を、コード・シード・Issue・PR・コミットメッセージ・スクリーンショットのどこにも入れない
- [ ] **見せる環境と本番を分ける**：面接で見せるのは、ダミーデータのデモ環境か操作の録画
- [ ] **非公開から公開に切り替える前に、履歴全体を確認する**：コード・コミットの作者名とメール・Issue・PR・コメントのすべてが公開される。いつ公開するかは未決（[open-questions.md](open-questions.md) の「リポジトリを公開するタイミング」）
- [ ] **Issue・コメントは、編集しても前の版が残る**：消したい内容を直したときは、編集履歴の古い版も消す
- [ ] **ヒアリングの生の記録は、リポジトリの外に置く**：リポジトリには、塾が特定されない一般的な書き方だけを書く
- [ ] **コミットのメールは noreply のアドレスにする**（[dev-env.md](dev-env.md)）
- [ ] GitHubの秘密の値の検知機能（secret scanning など）を有効にする。どこまで無料で使えるかは要確認

## 本番で動かすとき（実データ）

- [ ] **持つデータを最小限にする**：生徒情報は持たない（[business-rules.md](business-rules.md)）。講師も、名前とLINEのIDなど動くのに必要なものだけ保存する。LINEのプロフィール画像などは、要らなければ保存しない
- [ ] **権限チェックは必ずサーバー側で行う**：「他人の依頼は取り消せない」「承認待ちの人は何も見られない」を、APIで毎回確かめる。画面でボタンを隠すだけでは、URLを直接叩かれると防げない
- [ ] **役割を変えるAPIはMVPでは作らない**：権限を上げる操作の入口を減らす（[auth.md](auth.md)）
- [ ] **入力はzodで検証する**
- [ ] **SQLはDrizzle経由で書く**（値を文字列で連結しない。SQLインジェクション対策）
- [ ] **Reactで `dangerouslySetInnerHTML` を使わない**（XSS対策）
- [ ] **CookieはHttpOnly・Secureにする**：Better Authの既定値でどうなっているかは要確認
- [ ] **ログイン試行の回数を制限する**：Better Authにレート制限の機能がある（設定内容は要確認）
- [ ] **通信はHTTPSにする**：Railwayの提供ドメインでHTTPSが使えるかは要確認
- [ ] **本番データを手元に持ってこない**：自分のPCに落とすと、それ自体が漏洩の原因になる
- [ ] **本番DBにSQLを手で打たない**：スクリプト経由で書き換える（[operations.md](operations.md) の「スクリプトの約束」）
- [ ] **ログに個人情報やトークンを出さない**
- [ ] **辞めた講師をすぐ止められるようにする**：MVPの後（#15）。MVPの間は、辞めた人が出たら開発者が判断する（[auth.md](auth.md)）
- [ ] **依存パッケージの脆弱性を見張る**：GitHubのDependabotの通知を有効にする

## 塾と決めておくこと（試用を始める前に）

- [ ] 塾の情報を扱うシステムを個人で作って運用してよいか。口頭ではなく、メッセージなど記録に残る形で了承をもらう
- [ ] 開発者（自分）が管理権限（`superadmin`）を持ち、データを見られることを伝える
- [ ] 万一漏れたときの連絡先と手順を決める
- [ ] 利用目的を一言で示す簡単な説明文を用意する

講師の氏名などは個人情報にあたる。法的に何がどこまで必要かは、ここでは断定しない（要確認）。塾側にルールがあれば、それに従う。

## 就活での話し方

- 「実際に使われている」こと自体を話してよいかも、塾の了承の範囲で決める
- 利用者数や件数などの数字を出すときも、塾が特定されない形にする

## AIに渡す情報

- AI（チャット・Claude Code）に `.env` の中身、本番の接続情報、実データを渡さない
- AIへの約束は CLAUDE.md の「AIへのお願い」に書いてある
